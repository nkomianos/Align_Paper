# Prospective transport and task-capacity qualification

Status: prompt candidate implemented and unit-checked; fresh corpus NOT constructed; neural qualification NOT run or admitted. This is not a deployment-ready experiment or a paper result.

The original G0 result remains inconclusive. Its prompts/parser and completed evidence remain frozen in the remote checkout. New module src/validator_monoculture/transport_v2.py strips case identifiers from public examples, explicitly requires exactly the three parser-supported keys, and spells out JSON literals and escaping. It does not relax the parser, infer intended malformed values, expose private tests, or change semantic answers. The existing runner does not automatically use this candidate. Thirteen targeted prompt tests passed.

A useful next GPU run requires both a better interface and a viable task population. Before spending GPU time, construct and CPU-qualify 16 new DEV tasks across four security categories, with four distinct mechanisms per category rather than renamed copies. Each needs executable correct/vulnerable baselines, public functional checks, at least two independently repairable security defects, and a planted incomplete repair. Do not derive hidden cases by copying observed model failures from the completed G0. Source and record the provenance of every natural case; if these requirements cannot be met, do not launch.

Freeze the corpus and prompt before collecting 3 patches per family/task (96 patch generations) and 2 specification-only suites per family/task (64 suite generations). Estimated cached H100 runtime is roughly 25–45 minutes for 160 generations, plus CPU reconstruction; this is an estimate, not a mid-run cutoff. Use the existing pinned models, temperatures, sample seeds and 12-proposal budget. Do not add patch-aware generations at this qualification stage.

Interface gate: each family must deliver parseable suites on at least 90% of draws, meet the existing planted-detection minimum in every category, and meet the existing matched valid-budget reach rule. Capacity gate: both patch families must produce qualifying incomplete repairs on at least eight distinct DEV tasks, including at least two tasks per category; repetitions of one source or task cannot count as independent tasks. These are prospective engineering admission criteria, not confidence intervals or paper evidence. A failure stops expansion; do not keep editing prompts against the same observed tasks.

Conditional follow-up: only after both gates pass, prepare and freeze genuinely new confirmation tasks and a full analysis plan. Require natural-case evaluation and independent model/task replication before a paper recommendation. Neither passing this rehearsal nor the existing post-hoc metadata recovery establishes a monoculture effect. If fresh multi-defect tasks cannot be qualified promptly, pivot away from this formulation rather than repeat the original corpus.
